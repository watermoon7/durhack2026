# Genres Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A genre dropdown (Default, Rock) that changes how the backend writes the guitar and drum parts and which samples and mix the frontend plays them with.

**Architecture:** The backend gains a `genre` argument from `/api/midi` down to `render_notes`; only Rock changes notes (guitar power chords, drum accents). The frontend keys its sound and mix presets by genre and swaps every voice in place when the genre changes, then reloads every assigned part.

**Tech Stack:** Python 3.13 / FastAPI / mido / pytest; Vite + React 19 + TS strict + Tone.js 15 + smplr 1.1.

**Spec:** `docs/superpowers/specs/2026-11-15-genres-design.md`

## Global Constraints

- Default stays byte-identical: SHA-256 over `render_midi` for datasets `spy, aapl, tsla, gld, tlt` x instruments `kick, snare, hihat, synth, bass, pad, guitar` (in that order) is `19470c3bda251b638db778904a2784692af011f290afb72e6686172012a1b82e`.
- No new stage art. No request leaves localhost while the app runs.
- A genre missing a frontend sound or mix preset fails loudly.
- Adding a genre = one `GENRES` entry (backend) + one `GENRE_SOUNDS` and one `GENRE_MIX` entry (frontend).
- Backend runs with plain `uv run` (venv fixed). Zero warnings: `uv run pytest && uv run ruff check . --extend-exclude "* 2.py" && uv run mypy src tests`; `npm run lint && npm run build`.
- Another session edits `backend/src/market_band/config.py` (scenarios) and `fetch.py`: touch only the lines this plan names; never revert theirs.

## Review Focus

- Switching genre while playing: every piece keeps its stock, loop stays 64 beats, notes sound after samples load. Pinned in Task 3 (genre_check.mjs).
- Switching genre with nothing assigned, or twice quickly: no error, the last choice wins. Pinned in Task 3.
- Unknown genre in the API: 404, not a silent Default. Pinned in Task 1.
- Accent notes outside drum ranges must not trip the key/range or overlap tests for the wrong reason, and must never appear in Default. Pinned in Task 2.
- LM-2 samples load locally, not from smpldsnds.github.io. Pinned in Task 3 (offline_check.mjs).

### Task 2: Rock drum accents

**Files:** Modify `backend/src/market_band/config.py`, `algorithm.py`, `backend/tests/test_song.py`, `backend/tests/test_genres.py`.

**Interfaces:**
- Consumes: `render_notes(..., genre)` (Task 1), `ORNAMENT_TRIGGER`, `BEATS_PER_BAR`.
- Produces (`config.py`): `DRUM_ACCENT_NOTES = {"crash": 49, "tom_hh": 50, "tom_h": 48, "tom_m": 47, "tom_l": 45}`; `ROCK_DRUM_ACCENTS: dict[str, Literal["fill", "crash"]] = {"snare": "fill", "hihat": "crash"}`.
- Produces (`algorithm.py`): `drum_accents(ir, instrument, notes: list[Note]) -> list[Note]`, applied to drum parts only in Rock.
- Rules: **fill** (snare): on bar beat 4 (index % 4 == 3) with `activity >= ORNAMENT_TRIGGER`, drop that beat's snare notes and add four notes of 1/4 beat at notes 50, 48, 47, 45 (duration 0.25 x `NOTE_LEGATO`, velocity from the beat's intensity). **crash** (hi-hat): at the first beat of bar `b` when the mean activity of bar `b - 1` (bar 0 looks at the last bar, the loop) is `>= ORNAMENT_TRIGGER`, add note 49 for 1 beat x `NOTE_LEGATO` alongside the hi-hat hits.

- [ ] Write failing tests:
  ```python
  def test_rock_snare_fills_on_busy_fourth_beats():  # ir_with_activity([0.1, 0.1, 0.1, 0.9] * 2): notes at beats 3, 3.25, 3.5, 3.75 are 50, 48, 47, 45; no snare note starts in [3, 4) or [7, 8) other than the fill
  def test_rock_crash_follows_busy_bars():  # ir_with_activity([0.9] * 4 + [0.1] * 4): crash (49) at beat 4, and at beat 0 only if the last bar is busy (it is not here: no crash at 0)
  def test_default_drums_have_no_accents(dataset):  # parametrized; no note in DRUM_ACCENT_NOTES values for kick/snare/hihat
  def test_rock_drums_accents_only_on_their_pieces(dataset):  # kick never has accents; snare only toms; hihat only crash
  ```
  In `test_song.py`, `in_key_and_range` takes a `genre` and exempts `DRUM_ACCENT_NOTES` values on drum parts; `test_every_part_stays_in_key_and_range` and `test_no_same_pitch_overlap_in_any_part` are parametrized over `GENRES` too.
